# 离线部署说明（Linux amd64 / 达梦 DM8）

## 1. 使用范围与现场材料

本文从**离线介质已经送达现场**开始，所有操作只访问本机和内网 DM8。适用于全新部署，不用于覆盖已有实例。路径 `/media/offline`、内网主机名、schema 和账号均为占位，按现场实际替换。

本说明应与最终交付的离线版本配套使用；新版“密码只需非空”策略仍须随配套平台镜像交付，不表示现场服务器已经更新。

开始前必须具备：

- `gmssl-gui-linux-0.1.5.tar.gz`：发布包版本 0.1.5（版本号只标识整包发行，不改变内部 Java JAR 的 SNAPSHOT 文件名或 DM schema 基线版本）；包内顶层目录仍为 `gmssl-gui-linux-amd64/`，以兼容现有 wrapper。
- **成品镜像方式**需要交付方提供 `gmssl-gui-images-linux-amd64.tar`（含 engine/platform/web 三个 Linux amd64 镜像）；若选择此方式而缺少镜像 tar，停止部署。当前仓库尚未生成该镜像 tar。
- **本地 JRE 挂载方式**不需要 GmSSL 应用镜像 tar；需现场已有离线 Docker JRE 21 镜像（含 Java 21 与 OpenSSL）及 Nginx 镜像，缺少任一镜像时补齐匹配的离线介质，否则停止。
- Linux x86_64 主机、可用磁盘、Bash、tar、OpenSSL，以及具备 Docker 操作权限的管理员。
- 已离线安装并运行的 Docker Engine 24+ 与 Compose V2。若未安装，介质必须另外提供与服务器发行版、版本、架构匹配的 Engine、Compose 插件及全部依赖包和安装指引；由系统管理员按该发行版的离线流程安装，缺少介质则停止。本文不提供跨发行版通用安装命令。
- 可从容器网络访问的**内网 DM8**、专用业务 schema、数据库用户、DBA 离线管理工具与必要权限。应用包不包含达梦服务器。

现场不构建镜像、不安装源码依赖，不要求文件校验文件，也不访问镜像仓库。

```sh
uname -s
uname -m
docker --version
docker compose version
docker info >/dev/null
openssl version
```

应为 Linux / x86_64。任何依赖缺失都先补齐对应离线介质，不转为在线安装。

## 2. 解压与导入离线镜像

选择全新目录，不覆盖旧实例。压缩包顶层包含 `gmssl-gui-linux-amd64/`，因此实际部署根目录多一层：

```sh
umask 077
mkdir -p /opt/gmssl-gui-v1
tar -xzf /media/offline/gmssl-gui-linux-0.1.5.tar.gz -C /opt/gmssl-gui-v1
cd /opt/gmssl-gui-v1/gmssl-gui-linux-amd64
bash ./load-images.sh /media/offline/gmssl-gui-images-linux-amd64.tar
```

即使本机已有同名 tag，也必须显式导入本次配套镜像；若本机存在其他正在使用这些 tag 的旧实例，先停止本流程，按独立更新流程保留旧镜像后再导入。

```sh
docker image inspect gmssl-gui/engine:0.1.0-linux-amd64 >/dev/null
docker image inspect gmssl-gui/platform:0.1.0-linux-amd64 >/dev/null
docker image inspect gmssl-gui/web:0.1.0-linux-amd64 >/dev/null
```

以上为当前 compose 默认镜像名；配套版本若改变名称，以随包 compose 和镜像清单为准。三个镜像缺任意一个都停止。

## 3. DBA 初始化全新数据库

由 DBA 使用已经安装的内网 DM8 管理工具，确认连接的服务器、用户与当前 schema 正确，且确为本次新建空业务 schema，再顺序执行：

1. `artifacts/01_schema_dm8.sql`：创建业务结构。
2. `artifacts/migrations/00_schema_version_and_baseline.sql`：检查 11 张核心业务表、关键 BIT 列与凭据 VARBINARY 长度，登记或验证 `0.1.0 / success=1` 基线。

PL/SQL 块必须完整提交，末尾 `/` 按所用 DM 客户端规则处理，不按分号拆散。出现错误立即停止，保留脱敏错误码供 DBA 处理。该检查不是全部约束的完整结构比对。已有业务库不得重跑初始化 SQL；应由 DBA 走既有库基线与增量迁移流程。

数据库地址必须从**应用容器内部可达**。外部 DM8 的地址不要填 `127.0.0.1` 或 `localhost`，它们在容器中指向容器自身。由管理员确认内网路由、防火墙、DM8 监听与账号权限。

## 4. 只为新实例生成私有配置

```sh
cd /opt/gmssl-gui-v1/gmssl-gui-linux-amd64
bash ./init.sh
chmod 600 .env credentials.txt
```

`init.sh` 只用于首次部署，会产生 `.env`、`credentials.txt`、随机初始管理员密码、engine token 和 Vault 主密钥。已有任一配置文件时脚本停止；不要删除旧文件强制初始化。

在服务器本地私密编辑器中填写 `.env`，不要把密码放在命令行参数或聊天中。主要设置：

| 配置项 | 现场填写原则 |
|---|---|
| `SPRING_PROFILES_ACTIVE` | 保持 `dm` |
| `SPRING_DATASOURCE_URL` | `jdbc:dm://DM内网主机:端口?schema=业务SCHEMA`，替换占位值 |
| `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | DBA 提供的专用业务账号 |
| `GMSSL_BIND_ADDRESS` | 默认 127.0.0.1；需内网浏览器访问时设置本机指定内网地址并配置访问控制 |
| `GMSSL_WEB_PORT` | 分配未占用端口，默认 8088 |
| `GMSSL_SESSION_COOKIE_SECURE` | 直接访问内网 HTTP 时为 `false`；实际通过 HTTPS 访问时为 `true` |
| `GMSSL_BOOTSTRAP_USERNAME` / `GMSSL_BOOTSTRAP_PASSWORD` | 仅在 app_users 为空时用于创建初始管理员 |
| `GMSSL_VAULT_MASTER_KEY` / `GMSSL_ENGINE_TOKEN` | 保留初始化值并妥善备份，不随重启重新生成 |

内网 HTTP 传输没有 TLS 保护，只用于受控网络；HTTPS 由现场既有内网反向代理与证书方案提供。Secure=true 配合 HTTP 会出现登录后会话丢失。

配套新版本支持非空密码；已有数据库中的用户密码不会因修改 `.env` 而重置，旧账号继续使用原密码。不要把 bootstrap 配置当作已有用户改密工具。

Vault 中的材料依赖同一主密钥解密。丢失或替换主密钥会影响历史材料访问，必须与数据库、Vault 一致备份。`.env` 和 `credentials.txt` 不上传、不粘贴，不执行会完整展开秘密的 compose 配置打印。

## 5. 严格离线启动（两种方式二选一）

现场根据具备的离线镜像材料，选择以下两种启动方式之一：

### 方式一：成品镜像方式（默认，推荐）
若现场已导入交付方提供的三个成品镜像（`gmssl-gui/engine:0.1.0-linux-amd64`、`platform`、`web`），先做本地环境检查，再显式禁止在线构建和镜像获取：

```sh
cd /opt/gmssl-gui-v1/gmssl-gui-linux-amd64
bash ./check.sh
docker compose --env-file .env -f compose.yaml up -d --pull never --no-build --force-recreate
bash ./status.sh
```

这是成品镜像方式的现场启动命令，避免 `start.sh` 在镜像缺失时进入本地构建分支。配套包自带的 `start.sh` 会自动检测并以 `--no-build` 启动。

### 方式二：本地 JRE 挂载方式（无需 gmsslappimage.tar）
若现场未生成或未提供 GmSSL 成品镜像，但内网已有现成的 Docker JRE 21 基础镜像和 Nginx 镜像，可直接使用独立脚本挂载包内二进制产物运行：

```sh
cd /opt/gmssl-gui-v1/gmssl-gui-linux-amd64
bash ./check.sh
# 命令行参数 --jre-image 优先级高于环境变量 JRE_IMAGE
bash ./start-with-jre.sh --jre-image my-registry.local:5000/base/temurin:21-jre --nginx-image nginx:1.28-alpine
bash ./status.sh
```

**本地 JRE 挂载运行约束**：
1. **前提依赖**：所用 JRE 镜像必须包含可用 Java 21 运行环境及 OpenSSL 可执行程序（engine 服务底层密码原语依赖）；Nginx 镜像默认为 `nginx:1.28-alpine`（可通过 `--nginx-image` 或 `NGINX_IMAGE` 环境变量显式指定）。缺少任意镜像均会立即失败退出，绝不静默 fallback。
2. **零外网/零构建**：该方式直接将包内 `artifacts/*.jar`、Linux `gmssl-runner` 及 `web-dist` 以只读（`:ro`）挂载至容器中运行，同样遵循 `--pull never --no-build --force-recreate`，完全不联网。

## 6. 登录和功能确认

1. 使用浏览器访问现场配置的内网地址与端口；HTTPS 则访问实际内网代理入口。
2. 初次空库账号从私有 `credentials.txt` 获取；用户表已存在时使用原账号。
3. 页面打开不代表全部服务就绪：浏览器网络面板中，未登录的 `/api/v1/auth/me` 返回 401 正常；登录请求与登录后的 `/api/v1/auth/me` 应返回 200。
4. 查看项目、能力目录、密钥库与证书工具。只创建必要的验收项目，不做批量密钥生成或状态型签名。
5. 可选运行 `bash ./scripts/verify-native.sh` 做本地原生密码能力功能测试；它不是文件校验，也不替代浏览器登录和 DM8 业务验证。

### 常见问题

- **502**：先 `docker compose ps`，再本地查看 `docker compose logs --tail 100 platform engine web`；检查平台启动、容器到 DM8 的路由/权限、engine 通信及代理。根页面 200 不能证明后端正常。
- **登录后仍 401**：检查 HTTP/HTTPS 与 Secure Cookie 设置是否一致，以及浏览器是否携带会话；不要重置 Vault 主密钥。
- **数据库或结构错误**：停止上线，由 DBA 确认当前 schema 与迁移结果；不要重复执行初始化或清空表。
- 日志只在本地受控查看，对外反馈先去掉地址、账号、令牌、口令、Cookie 与 SQL 参数，绝不提供 `.env` 原文。

## 7. 证书库分类、信任边界与密码材料说明

1. **简单模式对称加密（SM4 CBC）约束**：
   - SM4 CBC 模式加密输出为纯密文，**不自动在密文头部拼接 IV**；
   - 加密生成或指定 16 字节 IV 后，用户**必须自行妥善记录并保存该 IV**；
   - 后续解密时必须显式提供该原始 IV（16 字节 Hex/字符串），**缺少原始 IV 无法恢复明文**，系统不假称可通过密文逆向还原。
2. **简单模式功能与向导入口**：
   - 简单模式精简为 4 项常用导航（工作台、密钥库、任务历史、项目与成员），首页工作台聚焦核心双卡（「制作证书」与「我的材料库」）；对称加解密等非证书工具彻底收敛隐藏，高级模式保持全量工具完整可用；
   - 证书向导提供 4 类清晰核心卡片：`单证自签名证书`、`自签名根 CA 证书`、`证书签名请求 (CSR)` 与 `快速签发服务证书`（排除中间 CA 与复杂 TLCP）；
   - 执行“快速签发服务证书”时若项目内暂无 CA 证书，向导提供直接「创建根 CA」切换按钮，不隐式破坏性自动建根；
   - 证书、CSR、链和托管密钥保存在 DM8 元数据及持久卷 `gmssl-gui-release_vault-data` 中，不应到容器临时目录找文件；证书向导成功页可按明确入口直接下载，私钥在“项目密钥 → 导出密钥”独立保管，证书下载默认不包含私钥或口令。
3. **密钥材料库与证书分类筛选**：
   - 密钥材料库在简单与高级两模式下均默认以证书树（按 CA 分组）展示，支持按项目切换或查看全部材料；
   - 证书树顶部提供签发 CA 过滤器（展示主体 CN、材料名、序列号尾号及过期标记），支持按主体、文件名、序列号或签发者检索；
   - 根 CA、中间 CA、CA 签发终端证书、自签终端证书、CSR/缺失上级/待解析或不支持材料属于材料分类；历史过期 CA 可查看，但已过期 CA 标记为不可签发；
   - **材料分类、CA 归属关系与完整信任链是不同概念**；拓扑展示不单独证明完整信任链已经验证；本版本吊销状态为 `UNCHECKED`，不执行 OCSP/CRL 查询，不能据此宣称证书未被吊销。
4. **CSR 与证书双向关联与追溯边界**：
   - 在证书树中，由 CSR 生成或与其公钥匹配的证书节点下提供关联 CSR 下载入口与来源标识；CSR 列表中提供反向定位/跳转至匹配证书的快捷通道，支持一对多与多对多真实公钥验签关联；
   - **关联匹配不等于签发血缘，未匹配不等于未签发**：CSR 仅作为公钥申请凭证，不是证书签发的唯一来源；直接生成自签名证书或 CA 直签证书均无对应 CSR，未匹配仅代表当前项目中未找到对应公钥的 CSR 文件，不构成未签发或证书无效的结论。

```sh
cd /opt/gmssl-gui-v1/gmssl-gui-linux-amd64
bash ./stop.sh
```

停止保留数据卷、配置与主密钥。不要删除数据卷或部署目录中的私有配置；后续启动继续使用它们。
