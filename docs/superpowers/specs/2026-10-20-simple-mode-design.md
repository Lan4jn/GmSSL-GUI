# 全站简单模式与证书全自动串联设计方案

## 1. 背景与目标

当前 GmSSL 工具箱拥有 80+ 原生算法命令及细粒度参数配置，功能全面但对仅需完成高频日常密码任务（证书生成、对称加密、哈希摘要、签名验签）的用户存在认知负担与操作门槛。
本方案依据用户在澄清访谈中的确认，在保留全部既有底层能力与安全契约的前提下，设计**全站简单模式（Simple Mode）**：
1. **默认简单模式**：登录后默认进入清晰、无噪的简单工作台，顶栏提供明显的“简单 / 高级模式”切换按钮（会话级内存记录，不使用持久化敏感存储）。
2. **首页首屏向导直达**：首页首屏中心突出展示带图标、中文用途及“开始向导”按钮的大任务卡，**“制作证书”主入口居中显著**，用户登录后无需进入工具分类列表即可一步触达向导，杜绝入口隐藏在二级页面横幅或参数抽屉中。
3. **向导分步体验与透明执行**：进入向导后展示清晰步骤条（选用途 → 填信息 → 确认配置 → 结果下载），当前步骤标题、上一步/下一步固定常驻；自动密钥生成与 CSR 在执行进度中透明展示，无需用户手动创建与拼接。
4. **六大高频场景入口显著**：生成密钥、制作证书、文件加解密、签名验签、哈希摘要、我的材料库，避免全屏自动弹窗打断工作，移动端和小屏幕保持良好可达性。
5. **证书全自动串联**：在制作证书时，用户无需先到密钥库生成私钥、再生成 CSR、再导入签发；后端自动串联 `生成私钥 -> 生成 CSR -> CA 签署 -> 格式转换与链封装`，一次点击直达证书与链文件下载。
6. **严格前置校验与错误防呆**：修正已有工作流中 CSR 与 CA 证书误选问题，提供真实内容类型与有效期校验，杜绝底层 native 报错抛出未知堆栈。

## 2. 界面交互与组件架构 (Frontend Architecture)

### 2.1 整体布局与模式切换
- **顶栏模式切换开关**：在全局顶部导航栏新增模式切换按钮（`简单模式` 与 `高级模式`），切换仅修改应用级会话响应式状态 `workbenchMode`，无需重刷页面，不将认证信息或模式状态存入持久存储。
- **简单工作台组件 (`SimpleWorkbench.vue`)**：
  - 采用轻量 Thin 组件设计，直接复用现有的 `types.ts`、`api.ts`、`forms.ts` 以及已有的 `KeyGenerateDialog` 等能力。
  - **首屏向导核心区**：居中突出展示“制作证书”大任务卡（含彩色图标、明确中文说明“自签名服务证书 / CA 签署证书”，配备醒目的“开始制作证书 ↗”主按钮）。
  - **六大场景平铺卡片**（图文卡片 + 明确操作按钮，小屏流式堆叠）：
    1. **制作证书 (向导)**：引导式单向操作，支持“制作自签名服务证书”与“通过已有 CA 签发证书”，首屏一步触达。
    2. **生成密钥**：快捷生成对称密钥（SM4/AES）或非对称密钥对（SM2/EC），默认自动安全加密托管。
    3. **文件加解密**：选择文件，选择对称算法（默认 SM4-CBC）与托管密钥/口令，一键执行加解密并下载。
    4. **数字签名与验签**：选择业务文件与签名私钥/公钥（默认 SM2-with-SM3），一键执行签名或验证。
    5. **哈希摘要**：文本或文件输入，选择 SM3 / SHA-256，即时获取计算哈希值（文本直接复制，大文件产物下载）。
    6. **我的材料库**：聚合当前项目的证书、私钥、对称密钥与输入文件，清晰标识状态与托管口令。

### 2.2 证书向导交互流程（四大简单入口）
根据用户最新明确反馈，简单模式在保留自签与已有 CA 一键签发的同时，显式包含根 CA 与独立 CSR 入口，杜绝“因缺少 CA/CSR 导致无法完成一键签发闭环”的问题：
- **四大简单 Profile 卡片**（排除专业二级中间 CA、CA_SIGN 与复杂 TLCP 双证）：
  1. **单证自签名证书 (SELF_SIGNED)**：自带私钥与自签 X.509 证书，适合点对点与测试。
  2. **自签名根 CA 证书 (ROOT_CA)**：建立独立信任根，供后续签发下级证书。
  3. **证书签名请求 (CSR)**：生成 PKCS#10 证书申请文件及私钥，供外部 CA 机构签署。
  4. **快速签发服务证书 (QUICK_ISSUE)**：基于已有 CA 证书全自动生成私钥、CSR 并签名，一步直达最终证书与证书链。
- **无 CA 引导机制**：若用户选择 `QUICK_ISSUE` 且项目中暂无可用 CA 证书，向导在签署机构步骤明确展示警告条，并提供显式「创建根 CA」按钮，直接切换至 `ROOT_CA` 创建流程；生成后刷新即可回到快速签发，杜绝假自签或 autoRoot 破坏证书权威。
- **步骤条与底栏固定**：
  - 步骤 1：选择证书类型（4 张通俗大卡）；
  - 步骤 2：填写主体标识（域名/IP、证书名称、有效期）；
  - 步骤 3：密钥与发行配置（QUICK_ISSUE 自动生成私钥与 CSR，隐藏手动 CSR 上传框）；
  - 步骤 4：执行与下载（成功页直呈证书/CSR/链下载按钮，私钥敏感独立分组）。
- **底栏导航**：底部居中固定“上一步”、“下一步”及“开始生成”按钮。

### 2.3 高级模式保留
- 切换至“高级模式”后，完整保留左侧边栏 80+ 真实算法目录、动态参数表单（含高级参数折叠抽屉）、审计日志、项目成员管理与系统用户管理，底层能力与逻辑完全保持不变。

## 3. 证书全自动串联后端工作流 (Backend Workflow)

### 3.1 串联编排设计
在 `CertificateWorkflowService` 中扩展全自动签发能力（或增强现有 `CA_SIGN` / `SELF_SIGNED` 流程）：
- **自签名证书场景**：
  1. 用户只需输入域名/IP、证书名称及有效期（默认 365 天）。
  2. 服务端自动调用 `generateKey` 生成 SM2 私钥并加密托管至 Vault；
  3. 服务端调用 `certgen` 签发自签名 X.509 证书；
  4. 自动保存证书至项目文件，生成证书链与解析校验；
  5. 成功页直呈 `xxx_cert.pem` 下载按钮，私钥安全留存在密钥库中。
- **通过已有 CA 签发证书场景**：
  1. 用户选择项目中的颁发者 CA 证书（仅列出真实解析合规的 CA 证书），输入被签发域名/IP 及用途（服务端证书/客户端证书）。
  2. **服务端自动串联**：
     - Step A: 自动调用生成服务，为待签发实体生成全新 SM2 密钥对（生成口令加密托管）；
     - Step B: 自动基于新私钥和用户填写的域名/IP 生成 CSR 请求文件；
     - Step C: 自动提取已选 CA 证书与私钥口令，调用 `reqsign` 签发最终实体证书；
     - Step D: 自动将 CA 证书追加至产物形成完整证书链 `xxx_chain.pem`。
  3. **产物输出与安全隔离**：
     - 成功页默认提供 `实体证书` 与 `完整证书链` 的直接下载；
     - 待签实体的全新私钥标记为独立敏感材料，明确说明“已加密留存至项目密钥库”，并提供二次授权下载，**严禁将私钥混入普通证书下载包**。
  4. **防呆与预检机制**：
     - **不自动创建 Root CA**：若项目中无可用 CA，界面明确提示“当前项目无可用 CA 证书，可先自建自签名证书或通过高级模式创建根 CA”，不隐式破坏性新建 Root CA。
     - **CA 有效期约束校验**：签发前检查申请天数是否超过 CA 证书剩余有效期，若超过则友好提示拦截。
     - **材料类型强校验**：服务端解析文件 PEM 标头与 DER 结构，坚决拦截把证书当作 CSR 传入 `reqsign` 的误操作。

## 4. 安全、权限与审计边界 (Security & Governance)

1. **会话与凭据隔离**：
   - 全程遵守现有 HttpOnly Cookie 会话与基于内存的 `X-CSRF-Token` 防护机制。
   - 简单模式下的所有材料生成与任务提交必须严格绑定当前项目的 `projectId`，杜绝越权访问。
2. **敏感信息保护**：
   - 自动生成的私钥文件口令由平台服务端加密存入 `key_credentials` 表，不在浏览器 URL、日志或无意预览中暴露。
   - 状态型私钥（LMS/XMSS 等）的单次晋升、禁止原始下载、禁止外部导入规则严格保持不变。
3. **安全审计追踪**：
   - 串联工作流中的每一个内部子任务（生成密钥、生成 CSR、签署证书）均保留独立的 Task/Job 记录与审计日志，操作轨迹完整可查。

## 5. 验收标准与测试规范 (Acceptance Criteria)

1. **首屏可达性与向导显式呈现 (UX/UI)**：
   - 用户登录后首屏无需进入任何工具分类页面即可直接看到向导入口大卡片，点击“开始制作证书”一步触达向导界面。
   - 简单模式向导清晰展示 4 类核心卡片（SELF_SIGNED、ROOT_CA、CSR、QUICK_ISSUE），排除中间 CA 与 TLCP；
   - QUICK_ISSUE 在无可用 CA 证书时提供清晰告警及「创建根 CA」快捷切换按钮，不隐式破坏性自动建根；
   - 向导各步骤具备固定标题、步骤条指示器以及“上一步 / 下一步”常驻按钮。
2. **单元测试与组件测试 (TDD)**：
   - `SimpleWorkbench.vue` 渲染六大场景卡片，点击切换场景表单正常。
   - 模式切换响应式同步，切换前后项目材料状态无丢失、无 IDOR 漏洞。
   - 错误材料（证书当 CSR、格式损坏、超期）在前后端均被准确截获并返回清晰中文提示，不出现底层 C 语言 native 报错。
3. **前后端接口与类型检查**：
   - 全量 TypeScript 严格类型检查通过（`vue-tsc --noEmit` exit 0）。
   - 全量前端 Vitest 测试通过（全套 107+ 用例无回归）。
   - 全量 Java 单元与集成测试（H2/达梦环境）通过。
4. **交付物一致性**：
   - 产物构建无多余哈希漂移，无外部网络依赖，保持现有离线运行部署能力。
