# GmSSL GUI 新版部署与平滑升级操作说明

本指南提供 GmSSL GUI 密码图形工具箱在 **Linux (amd64 / x86_64)** 架构、**外部达梦数据库 (DM8)** 及 **内网完全离线标准** 环境下的生产部署、日常维护、跨版本升级与证书下载操作说明。

---

## 一、架构特性与离线标准说明

1. **内网完全离线交付（零在线下载与编译）**：
   - 目标机器无需联网，无需访问 Docker Hub、Maven 或 npm，严禁在生产宿主机执行 `apt-get`、`apk`、`npm build` 或 `docker pull`；
   - 部署包含已编译的 Java 21 平台微服务（内嵌达梦官方驱动 `com.dameng:DmJdbcDriver18:8.1.3.140`）、Linux 纯静态 musl 原生执行器 `gmssl-runner` 及 Vue 3 前端静态资源；
   - **彻底移除文件哈希拦截屏障**：部署、升级、初始化过程**不包含任何文件 SHA 校验步骤**，无 `SHA256SUMS` 依赖。
2. **两份关键交付包说明**：
   - **应用发布包**：`gmssl-gui-linux-amd64.tar.gz`（包含全部二进制工件、管理脚本、达梦 DDL、前端页面与配置模板）；
   - **离线镜像归档**：`gmssl-gui-images-linux-amd64.tar`（包含 3 个微服务的预编译运行时镜像）。
   - **客观环境提示**：当前开发节点未安装 Docker Engine，真实离线镜像包（`gmssl-gui-images-linux-amd64.tar`）尚未在本机生成；若内网机器无外网访问权限，需先在外部联网 Docker 节点使用自带脚本一键生成。
3. **数据存储与持久化架构**：
   - **关系型数据**：外部达梦数据库 (DM8)，存储用户账号、角色权限、项目、作业元数据及加密口令；
   - **私钥保险箱**：本地 Docker 数据卷 `gmssl-gui-release_vault-data`，所有非对称私钥由 `GMSSL_VAULT_MASTER_KEY` 经 AES-256-GCM 主密钥加密存储；
   - **无内置数据库容器**：系统不编排 PostgreSQL 容器，避免资源冗余。

## 二、离线镜像制备（仅在联网 Docker 节点执行一次）

若目标服务器无法访问 Docker 官方镜像源，在任意可联网的 Linux/amd64 Docker 机器上执行：

```bash
# 1. 解压应用发布包
tar -xzf gmssl-gui-linux-amd64.tar.gz
cd gmssl-gui-linux-amd64

# 2. 执行离线镜像构建与导出工具（自动拉取轻量基础镜像并导出为单个 tar 归档）
./build-offline-images.sh

# 执行成功后将在当前目录生成：gmssl-gui-images-linux-amd64.tar
# 将该 tar 文件与应用发布包一并传输至内网目标服务器
```

## 三、内网首次全新安装部署

### 1. 达梦数据库表结构初始化（DBA 执行）
在外部达梦实例中为本系统创建独立的库模式与用户（例如用户名为 `GMSSL`，密码由企业统一管理），使用达梦管理工具 (DM Management Console) 或 `disql` 登录该用户，执行发布包附带的建表脚本：
```sql
-- 执行 artifacts/01_schema_dm8.sql 脚本
-- 包含 11 张业务表定义与必要索引，布尔列全部采用标准 BIT DEFAULT 0 NOT NULL
```

### 2. 解压与离线镜像装入
登录内网目标服务器：
```bash
# 1. 解压发布包
tar -xzf gmssl-gui-linux-amd64.tar.gz
cd gmssl-gui-linux-amd64

# 2. 导入离线镜像包（若服务器无外网访问）
./load-images.sh /path/to/gmssl-gui-images-linux-amd64.tar
```

### 3. 生成私有环境配置
```bash
./init.sh
```
- 自动生成 `.env` 私有配置文件与 `credentials.txt`（权限自动设为 `0600`）；
- 自动生成高熵随机应用通信 Token、Vault 主密钥与初始管理员密码（初始管理员默认用户名为 `admin`）；
- **编辑 `.env` 配置文件，配置外部达梦 DM8 真实连接信息**：
  ```bash
  SPRING_PROFILES_ACTIVE=dm
  SPRING_DATASOURCE_URL=jdbc:dm://<DM_HOST>:5236?schema=GMSSL
  SPRING_DATASOURCE_USERNAME=GMSSL
  # 注意：若数据库密码中包含 $ 等特殊字符，请使用单引号包裹或使用 $$ 转义
  SPRING_DATASOURCE_PASSWORD='YourActualSecurePassword'
  ```

### 4. 预检与启动全量服务
```bash
# 1. 结构与配置预检（无文件哈希拦截，快速核验必要工件与达梦配置完整性）
./check.sh

# 2. 启动服务（优先使用本地已导入的离线镜像，不拉取外网，不在线编译）
./start.sh

# 3. 验证底层国密原生执行器 SM3(abc) 标准向量测试
./scripts/verify-native.sh

# 4. 查看服务状态与端点健康响应
./status.sh
```

### 5. 访问与 HTTPS / 安全 Cookie 配置提示
- **默认监听**：回环地址 `http://127.0.0.1:8088`；
- **安全 Cookie 约束**：默认配置 `GMSSL_SESSION_COOKIE_SECURE=true`。浏览器仅在 HTTPS 连接下持久化会话 Cookie，生产环境必须前置反向代理（Nginx 或 Caddy 终结 TLS 并代理至 `127.0.0.1:8088`）；
- **纯内网临时 HTTP 访问**：若仅在局域网明文调试，请在 `.env` 中显式修改：
  ```bash
  GMSSL_BIND_ADDRESS=0.0.0.0
  GMSSL_SESSION_COOKIE_SECURE=false
  ```
  修改后运行 `./start.sh` 重启生效。

## 四、后续版本平滑升级规范（跨版本更新）

### 1. 升级核心原则与安全红线
1. **持久卷全局固定保护**：`compose.yaml` 顶级名称固定为 `name: gmssl-gui-release`，私钥保险箱卷全局固定为 `gmssl-gui-release_vault-data`。无论新版本解压至何目录，容器自动挂载同一数据卷，**私钥与托管文件不会因升级目录变更而丢失**；
2. **隔离解压升级（推荐）**：严禁直接在运行中的旧目录下解压覆盖；必须解压至新目录，通过 `upgrade.sh` 工具受控平滑迁移；
3. **主密钥一致性要求 (Fail-Closed)**：旧 `.env` 中的 `GMSSL_VAULT_MASTER_KEY` 必须保留，**严禁在新目录运行 `./init.sh` 生成新密钥**，否则历史私钥将永久无法解密；
4. **状态型私钥（LMS/HSS）不可逆规约**：若新版本运行中产生了状态型密钥签名消耗，**严禁通过恢复旧数据库或 Vault 快照进行回滚**，否则会导致一次性私钥索引复用安全灾难。

### 2. 标准平滑升级三步走

#### 步骤一：停止旧服务并执行离线冷备 (Pre-upgrade Backup)
在维护窗口停止旧版本服务，使用本地已有镜像进行一致性冷备：
```bash
cd /opt/gmssl-gui-v1/gmssl-gui-linux-amd64
./stop.sh

# 使用本地已有镜像进行离线冷备（--pull=never 严禁内网拉网，--entrypoint 覆盖入口点）
docker run --rm --pull=never --entrypoint /bin/tar --user 0:0 -v gmssl-gui-release_vault-data:/source:ro -v "$PWD":/backup gmssl-gui/engine:0.1.0-linux-amd64 czf /backup/vault-pre-upgrade.tar.gz -C /source .

# 由 DBA 使用达梦原生工具（如 dexp 或物理备份）对达梦数据库目标模式执行一致性备份
```

#### 步骤二：达梦数据库基线化与增量迁移（DBA 执行）
1. **已有生产库首次登记基线 (Baseline)**：
   若现有达梦库此前未初始化版本元数据表，请在 DM8 中执行：
   ```sql
   -- 执行 artifacts/migrations/00_schema_version_and_baseline.sql
   -- 脚本内置 PL/SQL 结构优先核验，校验 11 张核心表及 BIT、VARBINARY(4096) 类型通过后登记 0.1.0 基线
   ```
2. **执行新版本增量补丁（若新版本存在新字段/表）**：
   由 DBA 检查新版本 `artifacts/migrations/` 目录下的增量升级 SQL 并在达梦目标模式中执行。

#### 步骤三：解压新版本并执行平滑迁移工具
由于发布归档包含顶层目录，解压后需进入实际工程子目录：
```bash
# 1. 解压新版本到新隔离路径
mkdir -p /opt/gmssl-gui-v2
tar -xzf gmssl-gui-linux-amd64.tar.gz -C /opt/gmssl-gui-v2
cd /opt/gmssl-gui-v2/gmssl-gui-linux-amd64

# 2. 导入新版本镜像（若有新版本镜像更新）
./load-images.sh /path/to/new-images.tar

# 3. 预检与配置差异比对 (Plan 模式，纯只读无副作用)
./upgrade.sh --from /opt/gmssl-gui-v1/gmssl-gui-linux-amd64 --plan

# 4. 确认执行升级 (自动迁移旧配置、执行新预检、停止旧服务并启动新容器)
./upgrade.sh --from /opt/gmssl-gui-v1/gmssl-gui-linux-amd64 --apply --backup-done

# 5. 验证服务状态与算法执行器
./status.sh
./scripts/verify-native.sh
```

## 五、证书生成、成功页直接下载与密钥库导航

1. **证书快捷向导操作**：
   - 登录系统后进入“证书向导”，选择证书 Profile（根 CA、中间 CA、服务端证书、客户端证书、代码签名证书或 TLCP 双证书）；
   - 填写 Subject、SAN 扩展（支持 DNS 域名与 IPv4/IPv6 地址）及有效期；
   - 提交后由后端微服务通过受控管道调用底层原生执行器完成签发。
2. **成功页直接下载文件**：
   - 生成成功后，向导完成页提供直接下载面板：
     - **普通证书**：直接点击“下载证书 (.cer)”或“下载证书请求 (.csr)”保存到本地浏览器；
     - **TLCP 国密双证书**：签名证书（`sign_cert.cer`）与加密证书（`enc_cert.cer`）分别提供直接下载；
3. **敏感私钥隔离策略**：
   - 生成的非对称私钥安全加密存储在平台私钥保险箱（Vault）中，默认**不会**作为明文混入证书组进行下载，防止口令与私钥意外泄漏；
   - TLCP 私钥文件（`*_keys.pem`）作为高密项独立展示，下载需持授权角色进行显式确认。
4. **一键前往密钥库管理**：
   - 成功页提供“前往密钥库”导航按钮，点击后自动跳转至项目“密钥库/材料列表”，方便管理员集中查看指纹、有效期及调用关联算法。

## 六、日常运维与容器管控常用命令

在当前版本的部署根目录（例如 `/opt/gmssl-gui-linux-amd64/`）下执行：

| 操作目的 | 推荐执行命令 | 说明 |
|---|---|---|
| **查看服务与健康状态** | `./status.sh` | 展示容器运行状态及 Web 端点 HTTP 探测响应 |
| **启动/重启全部服务** | `./start.sh` | 使用本地成品镜像启动后台微服务容器 |
| **停止全部服务** | `./stop.sh` | 执行 `docker compose stop`，**绝不删除持久数据卷** |
| **实时查看运行日志** | `docker compose logs -f` | 跟踪 engine、platform 与 web 服务的输出日志 |
| **密码底层执行器自检** | `./scripts/verify-native.sh` | 执行容器内原生 SM3(abc) KAT 标准向量测试 |
| **离线冷备私钥数据卷** | 见本文第四节步骤一 | 使用 `--pull=never --entrypoint /bin/tar --user 0:0` 进行打包 |

## 七、运维规约与安全底线

1. **凭据安全**：
   - `.env` 与 `credentials.txt` 包含数据库账密与保险箱主密钥，权限必须锁死为 `0600`，严禁提交至版本控制或通过明文控制台打印；
   - 首次使用 `credentials.txt` 中的初始管理员密码登录后，请立即在 Web 界面重置管理员密码并安全删除该凭据文件。
   - **密码长度规范更新**：系统现已取消 12–72 字节的长度硬性限制，支持任意非空密码（包含短密码与超过 72 字节超长密码），并自动平滑兼容旧版本 BCrypt 密码散列。
2. **主密钥备份**：
   - 必须离线安全封存当前 `GMSSL_VAULT_MASTER_KEY`；只备份数据卷密文而丢失主密钥，将永久失去解密私钥的能力。
3. **有状态密钥单一权威**：
   - LMS/HSS 等状态型抗量子签名密钥与特定运行实例状态强绑定，严禁通过导入/还原旧快照覆盖已有运行状态。
